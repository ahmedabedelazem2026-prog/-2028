# تاكسي العاصمة — منصة النقل الذكي

واجهة ويب عربية متجاوبة للعميل والسائق والإدارة، مبنية على Firebase Authentication وRealtime Database للمشروع القديم `taxi-alasema-app-2026`.

## الوظائف الحالية في الكود
- حساب عميل بالبريد وكلمة المرور، وملف عميل في `customers/{uid}`.
- طلب رحلة بمكان الانطلاق والوجهة ونوع السيارة وموعد تقريبي وملاحظات.
- إنشاء الرحلة في `trips/{tripId}` مع نسخة خاصة بالعميل في `customer_trips/{uid}/{tripId}`.
- إنشاء طلب توزيع مختصر في `driver_requests/{tripId}` لا يحتوي رقم العميل أو بياناته الشخصية.
- تسجيل السائقين واعتمادهم يدويًا من الإدارة، والتحكم في حالة التوفر.
- عرض الطلبات للسائق المتاح، وقبول الرحلة بمعاملة Realtime Database لمنع قبولها مرتين.
- إظهار بيانات اتصال العميل للسائق بعد القبول، وبدء الرحلة وإنهاؤها.
- لوحة إدارة بإحصاءات الرحلات واعتماد السائقين والبحث في الرحلات.

## مسارات قاعدة البيانات الجديدة
- `trips/{tripId}`: سجل الرحلة الأساسي. يحتفظ أيضًا بالحقول القديمة التي كانت موجودة مثل `clientId`, `clientPhone`, `from`, `fromName`, `to`, `toName`, `status`, `createdAt`.
- `driver_requests/{tripId}`: بيانات مختصرة لتوزيع الطلبات على السائقين المتاحين؛ لا يتضمن هاتف العميل.
- `customer_trips/{uid}/{tripId}`: نسخة العميل لمتابعة حالة رحلاته دون قراءة جميع الرحلات.
- `driver_active/{uid}/{tripId}`: الرحلة النشطة للسائق بعد قبولها.
- `drivers/{uid}`: بيانات السائق وحالته واعتماده.
- `customers/{uid}`: ملف العميل.
- `admins/{uid}`: تفعيل حساب الإدارة بقيمة `active:true`.

## قواعد الأمان — مهم جدًا
يوجد ملف `database.rules.draft.json` كمسودة مراجعة فقط، **وليس منشورًا على Firebase**. لا تنسخه إلى قاعدة البيانات مباشرة قبل فحص قواعد مشروعك الحالية وتوافق تطبيق Android القديم؛ تطبيق القواعد الجديدة قد يمنع التطبيق القديم من قراءة/كتابة المسارات التي اعتاد عليها. لا توجد أي تغييرات منشورة على قواعد Firebase من هذا المستودع.

## ما لم يكتمل بعد — لا تعتبر المنصة جاهزة للتشغيل التجاري
1. لم يتم اختبار الموقع فعليًا على قاعدة Firebase الحية، ولم يتم تأكيد نشر آخر التحديثات على Vercel.
2. يجب مراجعة ودمج قواعد الأمان مع القواعد الحالية مع الحفاظ على وصول تطبيق Android القديم.
3. الطلبات التي ينشئها تطبيق Android القديم لن تظهر تلقائيًا في `driver_requests` إلا بعد تحديث التطبيق أو إضافة وسيط موثوق (مثل Cloud Function) ينسخ الطلبات القديمة إلى قائمة التوزيع.
4. لا يوجد تكامل خرائط Google حتى الآن: تحديد الموقع GPS، اختيار النقاط على الخريطة، حساب المسافة والمسار، وتتبع السيارة المباشر تحتاج تنفيذًا ومفتاح Google Maps Platform منفصلًا ومقيدًا بنطاق الموقع.
5. لا يوجد تسعير آلي أو دفع إلكتروني أو إشعارات Push حتى الآن. لا يتم اختراع سعر الرحلة أو إحداثياتها.
6. تسجيل الدخول الحالي بالبريد وكلمة المرور. تسجيل الهاتف برسالة SMS يحتاج تهيئة Phone Auth وreCAPTCHA.
7. الإلغاء الحالي للعميل متاح قبل قبول السائق فقط. سياسات الإلغاء والتقييمات والشكاوى والتقارير المالية تحتاج استكمالًا.
8. حساب الإدارة يتطلب إنشاء `admins/{uid}` يدويًا في Firebase بعد التأكد من UID الحساب الإداري.

## بيانات المشروع
- Firebase Project ID: `taxi-alasema-app-2026`
- Realtime Database: `https://taxi-alasema-app-2026-default-rtdb.firebaseio.com`
- إعدادات الويب موجودة في `firebase-config.js`. مفتاح الويب الظاهر في واجهة المتصفح ليس بديلًا عن قواعد Firebase؛ قيّده من Google Cloud APIs بحسب النطاقات وواجهات API المطلوبة.
- لا تضع Service Account أو مفاتيح خاصة في ملفات الموقع.

## التشغيل
يتم تقديم الملفات كواجهة ويب ثابتة، ويمكن ربطها باستضافة مثل Vercel. يلزم التأكد من نجاح النشر وإعداد نطاقات Firebase Authentication المصرح بها قبل الاختبار.

## 6. الخطة والآلية المقترحة لمزامنة GitHub بأمان تام

نظراً لأن التاريخين منفصلان (`Unrelated Histories`)، فإن تنفيذ `git push origin master` المباشر سيواجه تعارضاً إذا استهدف `main`، واستخدام `--force` مرفوض تماماً وفق الضوابط.

### الطريقة المقترحة الأكثر أماناً (Recommended Zero-Risk Strategy):

#### المسار الموصى به:
1. **المرحلة 1: تسجيل التغييرات المحلية في `master`:**
   - ضم كافة الملفات التشغيلية والصور الإعلانية الرسمية والتقارير في التزام نظيف موثق:
     ```bash
     git add -A
     git commit -m "feat(v2.1): complete CAPITAL TAXI smart platform v2.1 with bidding, cloud campaigns and brand assets"
     ```
2. **المرحلة 2: رفع الفرع المحلي `master` كفرع مستقل على GitHub دون المساس بـ `main`:**
   - رفع الفرع المحلي بأمان كامل ودون استخدام `--force`:
     ```bash
     git push -u origin master
     ```
   - **أثر ذلك:** يحفظ المستودع البعيد تاريخ `origin/main` القديم دون أي تغيير، ويضيف فرع `master` الجديد بكامل تاريخه وتعديلاته الحديثة.
3. **المرحلة 3: دمج التاريخين في `main` بأمان (Merge with unrelated histories) أو تعيين `master` كفرع افتراضي:**
   - يمكن إنشاء Pull Request رسمي على GitHub لدمج `master` إلى `main`، أو إنشاء نقطة دمج موثقة تحافظ على شجرة الكود لكلا الطرفين دون فقدان أي سطر تاريخ قديم:
     ```bash
     git checkout -b sync/v2.1-integration origin/main
     git merge master --allow-unrelated-histories -m "chore: merge local v2.1 platform into main preserving repository history"
     git push origin sync/v2.1-integration
     ```
